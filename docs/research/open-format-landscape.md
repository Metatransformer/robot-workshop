# Open-format interoperability landscape

Research date: 2026-10-17. Status: decision-support research; no implementation approval, installations, artifact execution, or interoperability experiments.

Inputs: [foundation decisions](../plans/workshop-foundation.md) and [MVP draft](../plans/metatransformer-mvp.md). Authored ordinary files are authoritative; documents-only inventions are complete projects. This report maps reusable conventions, not a commitment to ship every editor, converter or simulator.

## Recommendation: a small v0 profile

Adopt a versioned JSON manifest that references ordinary files, their roles and their derivations. Reuse existing formats within their domains instead of translating every invention into one workshop schema. An agent can edit text sources or use the owning application's API/CLI; Studio consumes an explicitly generated preview. Import, preview, author, export and execute are separate capabilities.

| v0 capability | Proposed profile | Boundary |
| --- | --- | --- |
| Documents and pictures | CommonMark Markdown, PNG/JPEG/WebP, constrained SVG, plain source-code display | No executable MDX/HTML/JS on open. Documents need no geometry or agent connection. |
| Structured project records | JSON manifest, local parts/BOM/evidence/inventory records, documented JSON Schema; CSV as a tabular exchange | Define only workshop semantics. Native CAD/electronics data stays native. Local records work without Supabase; hosted catalog IDs remain optional. |
| Visual model exchange | A tested glTF 2.0/GLB subset: meshes, transforms, basic materials, selected animation; Three.js preview | GLB is a delivery artifact, not a CAD feature tree, manufacturing approval or physics model. Plain self-contained GLB first; explicitly validate any external references or extensions. |
| Native-file preservation | Retain selected source bundles and dependency files, including unfamiliar formats | Download/source access and optional supplied preview do not imply native editing, conversion or execution support. |
| Representative execution | Explicit local TypeScript generator and one bounded planar four-bar experiment | Generated artifacts are linked to input revision, parameters and tool versions. No universal coupled solver. |

Initially, a Blender/FreeCAD/KiCad user can export a GLB/SVG/static preview themselves and include it alongside native files. Fixtures below should establish real interoperability before product claims. Automatic native-tool adapters are separately scoped work; they are not prerequisites for opening the project or viewing an already supplied preview.

The small manifest should identify each source and preview by artifact ID and path, then record a derivation's input content hashes/revision, output hash, tool/version and parameter/settings digest. A changed or missing input, changed recipe, or mismatched output marks the preview stale or unverifiable; it must not silently represent the current source. This is proposed lineage bookkeeping, not proof that the export is semantically correct.

## Reading the matrix

**Documented** means an upstream format or tool documents the capability. **Proposed** means our recommended usage, still requiring a pinned-version fixture. No end-to-end route below has been experimentally verified in this task. A documented exporter is not evidence of lossless round trips or physical accuracy.

**Authority follows the authored artifact**, not its extension alone. For an agent-authored generator, source plus inputs are authoritative and generated GLB/BOM are derived. For a manually authored BOM, the JSON itself is authoritative. An imported STEP may be the only source supplied; preserve it without inventing a missing parametric history. Never make a generated output a competing editable master without an explicit change of ownership.

**Cost classes:** L = ordinary parsing/rendering or a JS library, with validation still required; N = explicitly invoked native process/toolchain; W = WASM/kernel dependency requiring packaging and resource review. “L” does not mean trusted or execution-free when the input is source code.

## 1. Visual meshes and scenes

| Format / semantic scope | Tools and machine-generation route | Preview, authority and conversion risks |
| --- | --- | --- |
| **glTF / GLB**: runtime scene, mesh/material/texture data, transforms, skins and supported animations | Blender importer/exporter; Three.js loader/exporter; TypeScript glTF Transform `Document` and `NodeIO` for headless generation (**L**). [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [NodeIO](https://gltf-transform.dev/modules/core/classes/NodeIO) | Three.js is the natural preview. Keep generator, `.blend` or CAD source when available. glTF uses metres, radians and a right-handed Y-up convention. Node indices/names are not workshop identities. `.gltf` may reference external buffers/textures; GLB can also contain external references, so inspect URIs rather than trusting the suffix. |
| **USD / OpenUSD**: composed scenes, layers, references, variants, typed schemas and time-sampled properties | OpenUSD C++/Python APIs and tools; Blender USD import/export (**N**). Text `.usda` can be generated from TS, but composition validation still needs an implementation. `.usdc` is binary; `.usdz` packages assets. [OpenUSD overview](https://openusd.org/release/intro.html), [Blender USD](https://docs.blender.org/manual/en/5.4/files/import_export/usd.html) | Preserve layer/reference structure when it is authored source; use a separately exported GLB/image for v0 preview. Flattening loses composition/edit intent. Blender supports a subset, and schema/plugin/material support varies. Author `upAxis` and `metersPerUnit`; the release API documents a 0.01 m fallback, unlike glTF's metre convention. Prim paths are not durable global IDs. [Stage units](https://openusd.org/release/api/group___usd_geom_linear_units__group.html) |
| **`.blend`**: Blender-native project/data blocks, authoring state and linked/packed resources | Agent-authored Python through Blender's API/background CLI (**N**), not ad-hoc binary serialization from TS. [Blender file docs](https://docs.blender.org/manual/en/latest/files/blend/index.html), [CLI](https://docs.blender.org/manual/en/5.4/advanced/command_line/arguments.html) | Preserve the original plus external dependencies; use exported GLB or image/video previews. File scripts and drivers create an execution boundary. Disabling automatic scripts is useful but is not OS isolation. Do not auto-open a downloaded `.blend` in a privileged conversion process. |
| **OBJ + MTL + images**: widely exchanged geometry and basic material references | Blender and mesh tools; simple text generation from TS is possible (**L**, or **N** via Blender). [Blender OBJ manual](https://docs.blender.org/manual/nl/5.0/files/import_export/obj.html) | Preserve all sidecars. Optional mesh preview/conversion is feasible, but deferred from the smallest profile. Units, axes and material interpretation need explicit import settings; do not expect rigging, constraints, native modifiers or animation semantics to survive. OBJ sequences are not a replacement for an authored animation project. |

Blender's glTF documentation supports meshes, compatible materials, textures and selected animations. Export can split vertices at UV/normal discontinuities; supported animation paths and custom-property export are limited/configurable. The implication is a **supported visual subset**, not `.blend → GLB → .blend` identity. Preserve `.blend`; compare intended visible behavior on export/import. [Blender glTF documentation](https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html)

OpenUSD is materially broader than glTF, but adds composition, resolver and schema/runtime dependencies the MVP does not need. Preserve it now; defer full-stage interpretation. A USD physics schema or animated GLB does not supply or validate a solver.

## 2. Parametric CAD and manufacturing

| Format / semantic scope | Tools and generation route | Preview, authority and conversion risks |
| --- | --- | --- |
| **FreeCAD FCStd**: document objects, parameters/history, shapes and display information | FreeCAD Python/document API or `FreeCADCmd` (**N**). FCStd is a structured archive, not a JSON object to regenerate casually. [FCStd internals](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/File_Format_FCStd.md), [headless FreeCAD](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Headless_FreeCAD.md) | Preserve source and dependencies. Preview a derived mesh/GLB or static drawing. Recompute may require the original workbenches/object implementations. Cached shapes/thumbnails are not proof the model still recomputes. The cited official documentation repository is archived; verify details against the selected FreeCAD release. |
| **STEP / ISO 10303**: CAD product/shape exchange; supported assemblies, colors and metadata depend on application protocol and translator | FreeCAD/OCCT, Replicad and other CAD tools (**N/W**); invoke their APIs rather than hand-emitting complex topology. [ISO AP242](https://www.iso.org/standard/84300.html), [FreeCAD exchange](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Import_Export.md) | Preserve STEP; tessellate for browser preview. Record units, assembly placements and translator settings. STEP exchange does not promise reconstruction of FreeCAD sketches, expressions or feature history. Names/face numbering can change; test tolerances and identity mapping. |
| **STL**: triangular surface, usually manufacturing/mesh exchange | FreeCAD, Blender, OpenSCAD, JSCAD and slicers; straightforward mesh serialization (**L/N**) | Three.js mesh preview is cheap if later selected. Preserve native design source; triangle meshes do not encode parametric history, reliable part identity or a required unit field. Require an explicit unit assumption; normals, watertightness and tessellation tolerance need checking. [FreeCAD format table](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Import_Export.md) |
| **3MF**: packaged additive-manufacturing geometry, build items, units and extensible properties | OpenSCAD, open slicers and lib3mf; prefer an established writer (**N/W**, or an independently tested JS implementation). [Core specification](https://github.com/3MFConsortium/spec_core), [consortium](https://3mf.io/) | Preserve package and required extensions; derive a visual mesh for v0. Richer than STL, but a slicer project may include vendor settings another application ignores. Neither package validity nor a preview establishes printability. Check extension requirements, object/build IDs and unit handling. |
| **SVG / DXF**: vector drawings, profiles and layers; DXF covers CAD entities beyond the common 2D subset | Inkscape, FreeCAD and LibreCAD; SVG XML is easy to emit from TS, DXF should use a tested writer/tool (**L/N**). [SVG specification](https://www.w3.org/TR/SVG2/), [DXF reference](https://images.autodesk.com/adsk/files/autocad_2014_pdf_dxf_reference_enu.pdf) | SVG can be rendered as constrained static imagery; DXF preview can be a derived SVG. Preserve width/height/viewBox, units, origins and transforms. DXF `$INSUNITS` can be unitless; spline/arc flattening and font substitution can change fabrication dimensions. A drawing is not automatically a toolpath. |
| **OpenSCAD `.scad`**: code-based constructive geometry and parameters | Agent edits text; installed OpenSCAD CLI exports mesh/vector/image formats (**N**). [Official hosted manual](https://files.openscad.org/documentation/manual/Using_OpenSCAD_in_a_command_line_environment.html) | Source/includes are authoritative; STL/3MF/SVG previews are derived. Pin parameters and tessellation settings. Evaluation is explicit local work; do not treat a code preview as permission to run imports/includes. |
| **JSCAD JS/TS project**: code-based parametric 2D/3D geometry | `@jscad` modeling and CLI/npm packages (**L**, executing JS). [JSCAD docs](https://jscad.app/docs/), [units](https://jscad.app/docs/tutorial-02_modelingBasics.html) | Source and lockfile remain authoritative; bridge generated mesh to GLB. JSCAD is fundamentally unitless, commonly exported as mm. Verify selected release typings/module exports and triangulation; it is not a native STEP feature-history exchange. |
| **Replicad JS/TS project**: programmable CAD shapes over OCCT | Replicad + OpenCascade WASM, STEP/STL export and Three.js helpers (**W**). [Integration documentation](https://github.com/sgenoud/replicad/blob/main/packages/replicad-docs/docs/use-as-a-library.md) | Preserve source/parameters. Worker/WASM initialization, memory, tessellation and native-kernel version compatibility require a spike. Use when solid/STEP operations are actually needed, not as a requirement for documents or basic scenes. |

These are complementary paths: code-CAD or native CAD → exchange/manufacturing export → visual preview. Reverse arrows are not assumed. Keep source units and a documented transform into preview units, rather than rewriting native files to fit the viewer.

## 3. Electronics

| Format / semantic scope | Tools and generation route | Preview, authority and conversion risks |
| --- | --- | --- |
| **KiCad native**: `.kicad_pro`, `.kicad_sch`, `.kicad_pcb`, local libraries/rules and referenced assets | KiCad's documented S-expressions are machine-readable; an agent may edit them, with validation in the owning tool. `kicad-cli` automates checks/exports (**N**). [Schematic format](https://dev-docs.kicad.org/en/file-formats/sexpr-schematic/), [PCB format](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/) | Preserve native bundle. SVG is an inexpensive browser preview after native export; it does not retain connectivity or editable board semantics. Keep UUIDs, library links, sheets, net identities and reference designators distinct from workshop part IDs. Common coordinate values are mm; generation must preserve version and field syntax. [Common syntax](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/) |
| **SPICE netlists + model/includes**: circuit connectivity and device/behavior equations for a chosen dialect | ngspice and KiCad's simulation workflow; generate text and run the selected simulator separately (**N**). [ngspice documentation](https://ngspice.sourceforge.io/docs.html), [XSPICE](https://ngspice.sourceforge.io/xspice.html) | Show text and supplied result plots/CSV. Preserve model libraries and operating assumptions. A schematic-exported netlist is derived; an authored netlist can be source. Dialect, parameter suffixes, device support and code-model dependencies affect portability. Circuit simulation does not establish PCB layout or firmware correctness. |
| **Gerber + drill files**: fabrication layer images/attributes and hole/tool instructions | KiCad exports; GerbView/gerbv inspect (**N** for our proposed adapter). [Ucamco specifications](https://www.ucamco.com/en/guest/downloads), [KiCad CLI](https://docs.kicad.org/10.0/en/cli/cli.html) | Preserve as manufacturing deliverables and derive image previews if needed. Units, coordinate precision/origin, layer functions, polarity and plated/non-plated holes must agree. They do not recover native schematic intent or a lossless editable PCB. |

The current KiCad 10 CLI documents schematic and PCB SVG, BOM/netlist exports, manufacturing outputs, and PCB GLB/STEP. This gives a concrete reuse route without a workshop EDA editor. Pin CLI version and export flags; schematic sheets, fonts, libraries and 3D-model dependencies can affect output. No KiCad process is needed to view an already exported SVG. [CLI reference](https://docs.kicad.org/10.0/en/cli/cli.html)

## 4. Robotics, mechanisms and firmware

| Format / semantic scope | Tools and generation route | Preview, authority and conversion risks |
| --- | --- | --- |
| **URDF / Xacro**: robot links, joints, visuals/collisions/inertias; Xacro expands XML macros | ROS urdfdom/Xacro and robot tooling; TS can emit URDF, while Xacro processing needs its supported environment (**N**). [Xacro](https://github.com/ros/xacro), [official kinematics comparison](https://sdformat.org/tutorials/specification/spec_model_kinematics/) | Preserve Xacro/includes as source when used, with URDF as generated output. A future viewer can use resolved geometry and joint states; a static GLB is enough for v0. URDF's native kinematic topology is a tree, so a four-bar loop cannot be faithfully reduced to plain URDF. Resolve package resources and frame/unit conventions explicitly. |
| **SDF / SDFormat**: robot/world description, links/joints, sensors and simulation-related properties | libsdformat/Gazebo; XML generation is practical, native parsing and simulation separate (**N**). [SDFormat](https://sdformat.org/), [frame/graph semantics](https://sdformat.org/tutorials/specification/pose_frame_semantics/1.5/) | Preserve original SDF plus models/assets/plugins. Graph topology supports closed loops; that does not establish every engine's behavior. Converting URDF may lump fixed joints or alter representation; mapping/link identity and plugin support need explicit checks. Preview exported visuals rather than starting Gazebo when opening a project. |
| **MJCF**: MuJoCo-specific physical model, actuators, sensors, tendons/constraints and other supported entities | MuJoCo XML/compiler and native bindings (**N**); TS can generate XML for a declared version. [MuJoCo modeling](https://mujoco.readthedocs.io/en/stable/modeling.html) | Preserve MJCF/assets and simulator settings. Loops require appropriate constraint modeling around the body hierarchy. URDF covers only a subset of MJCF. Compiled defaults, inferred inertia, collision geometry and equality-constraint behavior can change the result; mesh preview is not simulator equivalence. |
| **Firmware/controller project**: C/C++/Rust/TS or other source, build configuration, board definitions and dependencies | Existing toolchains/CLIs, e.g. Arduino CLI (**N**); the agent edits native source/configuration. [Arduino CLI](https://docs.arduino.cc/arduino-cli/getting-started/) | Plain code preview and downloadable source first. Preserve board/toolchain/library versions; ELF/HEX/BIN are derived target artifacts. Compile, emulator execution and hardware upload are different operations. No automatic hardware control; a compiling program is not a physically tested device. |

For the one proposed experiment, a bounded TS planar four-bar calculation can output poses and a pen trace without selecting a general simulator. Record link lengths, angle/branch, fixed anchors and singular/unreachable cases; state omitted dynamics. Planck offers JS/TS revolute joints but documents iterative-solver approximations. Rapier requires loop-closing constraints beyond its tree multibodies. These are candidates, not physical-validation guarantees. [Planck limits](https://piqnt.com/planck.js/docs/limitations.html), [Rapier constraints](https://rapier.rs/docs/user_guides/javascript/joint_constraints/)

## 5. Multidomain simulation

| Format / semantic scope | Tools and generation route | Preview, authority and portability risks |
| --- | --- | --- |
| **Modelica `.mo` + libraries**: equation/algorithm source and acausal physical connectors across domains | OpenModelica/compiler scripting; agent writes source, TS invokes the native compiler if selected (**N**). [Language](https://modelica.org/projects/language/), [scripting API](https://openmodelica.org/doc/OpenModelicaUsersGuide/v1.25.4/scripting_api.html) | Preserve source/libraries; show text and supplied plots. This is an existing multidomain modeling language, not merely a mesh descriptor. Compiler/library compatibility, external functions, initialization and solver settings require testing. Electrical/fluid/thermal connections cannot all be treated as directed scalar signals. |
| **FMI / FMU**: standardized executable model interfaces; FMU packages XML plus binaries and/or source/resources | OpenModelica can export; FMI importers such as OMSimulator/FMPy execute supported units (**N**). TS orchestration is possible, but is not a browser runtime. [FMI 3.0.2](https://fmi-standard.org/docs/3.0.2/) | Preserve FMU and originating source when supplied. Model Exchange delegates integration; Co-Simulation packages model execution/solver behavior; Scheduled Execution delegates scheduling. Binary FMUs target platform tuples and may require external runtimes/licenses. An FMU is neither necessarily source-available nor universally executable, and FMI does not choose the orchestration algorithm. |
| **SSP**: system composition, connectors, parameterization and packaging of component models/resources | OMSimulator and other participating tools; TS can generate XML/ZIP, validated against the selected SSP version (**N** to execute contained models). [SSP 2.0.1](https://ssp-standard.org/docs/2.0.1/), [OpenModelica tool overview](https://openmodelica.org/images/M_images/250908-ModelicaTutorial-PeterFritzson-2025.pdf) | Preserve system/parameter sources and referenced components. Show metadata/results rather than running a package. FMI version/features, units, parameter mappings, external resources and co-simulation settings remain dependencies. SSP is relevant to simulation composition, not required as the container for documents, inventory and every invention. |

Defer these execution adapters. File preservation and result/evidence display meet the current interoperability boundary. “Open interface” does not mean an enclosed model is open source, has compatible binaries, includes its authoring equations, or has adequate fidelity for a claim.

## 6. Documents, records, BOM and evidence

| Format / semantic scope | Tools and generation route | Preview, authority and conversion risks |
| --- | --- | --- |
| **Markdown** | CommonMark parsers and ordinary editors; straightforward agent/TS authoring (**L**). [CommonMark](https://spec.commonmark.org/) | Primary prose/build guidance. Declare supported extensions rather than assuming identical Markdown dialects. Resolve links/images within the selected revision; treat raw HTML as outside the baseline. |
| **JSON + JSON Schema** | Ordinary TS serializers and schema validators (**L**). [JSON Schema 2020-12](https://json-schema.org/draft/2020-12) | Primary manifest/record format or clearly labelled generated data. A schema validates shape and declared constraints, not a datasheet claim or physical correctness. | **CSV** | LibreOffice and standard CSV parsers/writers; useful BOM/measurement exchange (**L**). [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180) | Table preview/import mapping. Specify encoding, delimiter, columns, units and null handling; quoting is meaningful. CSV does not carry a universal BOM schema. Prevent spreadsheet formula interpretation on exports; avoid losing long IDs, leading zeros or unit distinctions. |
| **SVG** | Inkscape, diagram tools and XML generators (**L**, optional **N** rasterization) | Reusable static diagrams or engineering previews. Preserve original; display under a constrained image policy, not arbitrary active DOM. Fonts/external resources/scripts and viewBox scaling need validation. [SVG](https://www.w3.org/TR/SVG2/) |
| **Jupyter `.ipynb` / Quarto** | Notebook format stores cells, metadata and outputs; Quarto renders selected document/notebook files (**N** if executing kernels). Use supplied static previews; opening must not execute cells. Saved outputs can be stale, active or environment-dependent. Kernel, library versions and execution order are separate evidence. |
| **RO-Crate** | Existing JSON-LD metadata alongside files for aggregation/provenance/exchange (**L** to construct metadata). [RO-Crate](https://www.researchobject.org/ro-crate/specification/1.2/introduction.html) | Useful precedent if richer research interchange becomes material; defer required adoption. It can describe files without replacing them. Do not grow the v0 manifest into a general ontology or make linked metadata imply verified provenance. |

## Cross-format rules worth preserving now

1. **No universal identity:** native UUIDs, node names, array indices, CAD face IDs and simulator link names have different scopes. Keep a mapping to stable artifact/part IDs when a preview supports picking; invalidate/rebuild it on conversion. Do not infer BOM quantity from mesh count or treat a supplier URL as a part definition.
2. **No implicit coordinate conversion:** record source units/axes and applied transforms. Metres↔millimetres, Y-up↔Z-up, radians↔degrees, mirrored boards and drawing viewBox scale need fixture checks. Geometry units and physical quantity units are separate.
3. **Package dependencies deliberately:** preserve local libraries, includes, textures, fonts, model files and licenses needed by the chosen source. Resolve only allowed project resources; missing dependencies are visible, not silently substituted. Do not claim a single filename is a complete project.
4. **Source and result lineage:** outputs identify source revision/hash, explicit tool/version/settings and relevant assumptions. Compare those recorded inputs with current files to detect stale previews; missing lineage means freshness is unknown. A native-file save/recompute or converter upgrade can change meaning. A preview cache is disposable; original artifacts and selected releases are not.
5. **Text does not imply safe execution:** JS/TS, Python, Xacro expressions, notebooks, netlist control/code models and FMU binaries need distinct execution handling. Parsing a selected static preview should not invoke a compiler, install dependencies, load arbitrary plugins or run the project's generator.

## Openness and redistribution: separate questions

The matrix identifies published formats and open-source implementations, not a single license regime. glTF, SVG, JSON Schema, Modelica/FMI/SSP and 3MF have their own specification terms; STEP is an ISO standards family, and DXF/Gerber have published vendor-maintained references. Access to a specification is different from implementation licensing, patent terms or permission to redistribute a particular artifact.

Blender explicitly distinguishes its GPL software from user-created artwork/data. KiCad separately documents software and library terms, including a library exception. Neither statement clears rights to arbitrary downloaded meshes, symbols, manufacturer models, fonts, textures or datasheets. [Blender license](https://www.blender.org/about/license/), [KiCad licenses](https://www.kicad.org/about/licenses/), [KiCad library terms](https://www.kicad.org/libraries/license/index.html)

OpenUSD documents TOST licensing. JSCAD, glTF Transform and Replicad identify MIT licensing; Replicad's OCCT dependency has LGPL 2.1 plus an exception, so inspecting the top-level npm license alone is insufficient. FMUs/plugins/model libraries can add their own redistributable or proprietary dependencies. Review exact pinned distributions and assets before bundling native/WASM runtimes; this report selects no project license and promises no legal compatibility. [OpenUSD](https://openusd.org/release/intro.html), [JSCAD](https://jscad.app/docs/), [glTF Transform](https://github.com/donmccurdy/glTF-Transform), [Replicad](https://github.com/sgenoud/replicad), [OCCT](https://dev.opencascade.org/doc/overview/html/occt_public_license.html)

Use the [Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator) on visual fixtures, plus numerical dimensions/pose checks and visual inspection. Schema-valid files alone do not establish appearance, CAD semantics or mechanism behavior. Native-tool fixtures are explicit local development tasks on known inputs; they are not automatic execution of imported user projects.

## What stays outside v0, and what remains unknown

- Preserve but do not require first-party interpretation of `.blend`, USD layers, FCStd/STEP, STL/3MF/OBJ/DXF, KiCad native/manufacturing files, URDF/Xacro/SDF/MJCF, firmware projects, Modelica/FMU/SSP and notebooks. Supplied safe previews can make any of these useful immediately.
- Defer native format editors, generalized conversion services, automatic manufacturing preparation, browser-hosted CAD kernels, FMU/circuit/robot solver execution and hardware upload adapters. A user may still use external tools directly; file interoperability is broader than integrated runtime support.
- Select and pin actual releases before advertising routes. This pass read documentation from mixed maintained/release branches, including Blender 5.1/5.4 pages, KiCad 10, OpenUSD release docs and an archived official FreeCAD documentation repository. Documentation availability is not evidence those versions are installed, compatible or the final support target.
- Unknowns for spikes: Node/WASM packaging, native CLI behavior on supported OSes, geometry tolerances, missing-reference behavior, SVG/font fidelity, Blender custom-property survival, CAD identity mapping and artifact complexity limits. No converter benchmarks or physical validation were run.
- The next architecture decision is the small preview/exchange profile and ownership contract. It need not choose every future adapter or make all source formats implement one shared simulation graph.
